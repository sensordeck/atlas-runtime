# Track C — Portal + Certification Roadmap
# Status: ROADMAP
# Scope: Post-V1 Productization and Certification

---

## 1. Purpose

Track C defines Atlas customer-facing productization after V1 runtime governance freeze.

Track C turns Atlas governance outputs into customer workflows.

Track C is NOT required for V1 runtime release.

---

## 2. Core Direction

Track C focuses on:

- Portal frontend
- evidence window viewer
- limitation viewer
- governance timeline viewer
- supplier / OEM comparison workflow
- pilot onboarding workflow
- Atlas Verified Sensor workflow
- certified sensor registry
- static 1-page launch PDFs

---

## 3. Portal Principle

Portal must be a renderer first.

Portal MUST consume:

- portal_payload.json
- section_index.json
- limitation render blocks
- governance window render blocks
- comparison render blocks
- role render blocks

Portal MUST NOT become:

- hidden decision engine
- AI scoring system
- deployment approval system
- legal adjudication system
- certification override system

---

## 4. Customer Trust Surfaces

Track C should produce customer-facing surfaces:

- CTO Governance Brief
- Runtime Discovery Brief
- Supplier / Dispute Comparison Brief
- Pilot Mode Brief
- Evidence Window Example
- Replay Visibility Example
- Limitation Preservation Example

Full technical report is not V1 launch blocker.

Evidence-first communication is preferred.

---

## 5. Atlas Verified Sensor Direction

Atlas Verified Sensor means:

- evidence-backed runtime governance visibility
- reference-domain comparison when available
- limitation-preserved certification boundary
- replay admissibility disclosure
- no fake certainty

Atlas Verified MUST NOT mean:

- perfect sensor
- legal fault shield
- absolute timing truth
- deployment approval
- production readiness by default

---

## 6. Supplier / OEM Workflow

Track C should support:

- OEM runtime evidence upload
- supplier evidence comparison
- replay-visible deviation review
- limitation delta review
- neutral governance comparison
- pilot decision support

Comparison visibility is not adjudication.

---

## 7. Pilot Workflow

Pilot workflow should support:

- controlled pilot scope
- runtime evidence retention
- governance window review
- limitation escalation
- acceptance criteria
- rollback boundary
- supplier participation boundary

Pilot approval is an organizational decision.

Atlas provides governance visibility, not final deployment authorization.

---

## 8. Relationship to Track A and Track B

Track C consumes:

- Track A runtime governance foundation
- Track B reference-domain outputs when available

Track C MUST NOT redefine:

- replay admissibility
- limitation semantics
- governance comparison boundary
- authority boundary
